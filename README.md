# Кидз Комбо × Снежные шары — режиссёрский тритмент

Одностраничный статический сайт-«фильм»: каждый слайд — остановка камеры с зацикленным видео и текстом поверх, переход между слайдами — видео пролёта. Чистые HTML + CSS + JS, без сборки и зависимостей. Работает двойным кликом по `index.html` (`file://`) и на GitHub Pages.

```
assets_src/          исходники новых и обновлённых материалов (в git не хранится) — скрипт их не меняет
  video/             stop__*.mp4, tr__*__*.mp4, still__*.webp|png|jpg
  audio/music.*      фоновая музыка
  content/           картинки/видео для шаблонов слайдов
  image/             favicon.png, og-preview.png
assets/              всё сжатое + manifest.js — скрипт только дополняет; вручную можно лишь удалять записи
  moodboard/         мудборды раздела «Как устроен мир»: исходные PNG, WebP для просмотра и превью — кладутся вручную, скрипт их не трогает
fonts/               Shantell Sans (заголовки), Onest (текст) — woff2, OFL
scripts/optimize.ps1 сжатие ассетов и генерация манифеста (+ optimize.cmd для двойного клика)
index.html, style.css
config.js            тур, контент слайдов, склейки, заглушки — это главный файл для правок
player.js            видеодвижок: буферы, граф, поиск пути, склейки, заглушки
app.js               навигация, текст слайдов, музыка, экран загрузки
debug.js             отладочный оверлей
```

## Добавить новые кадры из Kling

Нужен FFmpeg: `ffmpeg` и `ffprobe` должны быть в PATH (например, `winget install Gyan.FFmpeg`, затем откройте новое окно терминала).

Скрипт работает **в режиме дополнения**: в `assets_src/` кладутся только новые или обновлённые материалы, старые исходники не нужны. Всё, что уже есть в `assets/` и `assets/manifest.js` (ролики, постеры, музыка, картинки), остаётся как есть: скрипт ничего не удаляет и не перекодирует файлы, для которых в `assets_src/` нет исходника.

1. Положите новые файлы в `assets_src/video/` по соглашению об именах (id — латиница, цифры, `-`, одиночное `_`):

   | Имя файла | Что это |
   |---|---|
   | `stop__<id>.mp4` | цикл остановки |
   | `tr__<from>__<to>.mp4` | пролёт от `<from>` к `<to>` |
   | `tr__<to>__<from>.mp4` | необязательный «ручной» обратный пролёт; без него обратный делается реверсом |
   | `still__<id>.webp` / `.png` / `.jpg` | картинка для остановки, у которой ещё нет цикла (медленный наезд Ken Burns) |
   | `once__<id>.mp4` | ролик, который играет один раз и остаётся на последнем кадре (финальный логотип). Не цикл: стык не проверяется, цвет размечается как BT.709, чтобы фон страницы совпадал с фоном ролика. Играет после прихода на остановку, а не во время растворения; при повторном заходе — снова с начала |

2. Посмотрите план, ничего не меняя (FFmpeg для этого не нужен):
   ```
   powershell -ExecutionPolicy Bypass -File scripts\optimize.ps1 -DryRun
   ```
   Для каждого исходника показано действие: `новый` — такого файла в `assets/` ещё нет; `обновить` — исходник новее готового файла; `пропустить` — готовый файл не старше исходника; `в манифест` — файл уже сжат, но записи в манифесте нет. Строка «Без изменений» перечисляет остановки, рёбра и музыку, которые останутся нетронутыми.
3. Запустите `scripts\optimize.cmd` (двойной клик) или в PowerShell:
   ```
   powershell -ExecutionPolicy Bypass -File scripts\optimize.ps1
   ```
   Скрипт сжимает только исходники из `assets_src/`, делает реверсы пролётов, постеры (первый и последний кадр в WebP), дописывает или обновляет их записи в `assets/manifest.js` и печатает таблицу «было / стало». Кодирование идёт во временную папку: файл в `assets/` заменяется только после успешного кодирования.

   Скрипт останавливается и ничего не меняет, если:
   - в `assets/manifest.js` указан файл, которого нет в `assets/` (скрипт перечислит такие файлы) — верните их командой `git restore assets/` или удалите ненужную запись (см. ниже);
   - `assets/manifest.js` не читается или его нет, хотя в `assets/video/` есть ролики — `git restore assets/manifest.js`;
   - не найдены `ffmpeg` или `ffprobe`.

   Предупреждения внизу вывода (проверки стыков считаются только для добавленного и обновлённого, у старых записей значения прежние):
   - **цикл с рывком на стыке** (первый и последний кадр сильно различаются) — попробуйте `loopMode: "pingpong"` или перегенерируйте цикл;
   - **пролёт не стыкуется с циклом цели** — поставьте этому ребру `join: "push"` или догенерируйте недостающий кусок;
   - **файл проигнорирован** — имя не по соглашению;
   - **не используются манифестом** — файлы в `assets/`, на которые больше нет ссылок (например, старый авто-реверс после появления ручного обратного пролёта). Они не удаляются.
4. Добавьте id в `tour` в `config.js` и напишите контент слайда (ниже).

Обработанные исходники можно оставить в `assets_src/` (при следующих запусках они пропускаются) или убрать: записи и файлы в `assets/` останутся.

### Заменить или убрать материал

- **Заменить.** Положите исходник с тем же именем. Если он старше готового файла (например, скопирован с сохранением старой даты), скрипт его пропустит; тогда запустите с `-Force`. Флаг перекодирует все исходники из `assets_src/`, но файлы без исходника по-прежнему не трогает. Обновлённый пролёт `tr__a__b` пересобирает и свой авто-реверс `b → a`; ручной обратный пролёт не перезаписывается.
- **Пересобрать один файл или уменьшить разрешение.** `-Only <имя без расширения>` обрабатывает только указанные исходники (несколько — через запятую), `-MaxHeight 720` уменьшает видео выше 720 px, меньшие не увеличивает. Без `-MaxHeight` разрешение остаётся исходным. Например: `powershell -ExecutionPolicy Bypass -File scripts\optimize.ps1 -Only stop__scene08 -Force -MaxHeight 720`. Так собран `scene08`: исходник 1920×1080, готовый файл 1280×720 — в 1080p он подтормаживал на слабых машинах. При следующей пересборке с `-Force` добавляйте `-MaxHeight 720`, иначе он снова станет 1080p.
- **Ручной обратный пролёт вместо авто-реверса.** Положите `tr__<to>__<from>.mp4`. Прежний `….rev.mp4` останется в `assets/` и попадёт в список «не используются манифестом».
- **Убрать.** Скрипт сам ничего не удаляет. Удалите запись из `assets/manifest.js` (остановку в `stops` или ребро в `edges`) и id из `tour` в `config.js`, затем файлы: `git rm assets/video/<имя>.mp4 assets/poster/<имя>.first.webp assets/poster/<имя>.last.webp`. Это единственная допустимая ручная правка манифеста.

Код трогать не нужно: движок сам находит путь по графу. Если между соседями по туру нет ни одного пролёта, играет заглушка; как только нужный `tr__…` появится и скрипт обновит манифест, вместо заглушки пойдёт видео.

Путь между любыми двумя слайдами — кратчайший по рёбрам (с учётом реверсов). Промежуточные остановки проезжаются без паузы, промежуточные сегменты ускоряются (`transitSpeed`). Например, при рёбрах `master→globes` и `master→tree` путь `globes → tree` = реверс `master→globes` + `master→tree`.

## Контент слайдов

`config.js → stops.<id>.content`. Отсутствующие поля не рендерятся.

```js
scene09: {
  content: {
    layout: "text",          // none | title | text | text-image | gallery | palette | quote | video
    side: "left",            // где в кадре свободное место: left | right | center | top | bottom
    theme: "dark",           // dark — светлый текст на тёмной подложке, light — тёмный на бумажной карточке
    kicker: "Сцена 09",      // рукописная пометка над заголовком
    title: "Снежные шары",
    text: "Абзац…",          // строка или массив строк (несколько абзацев)
    images: ["assets/content/ref1.webp", { src: "assets/content/ref2.webp", caption: "Подпись" }],
    caption: "Подпись",
  },
},
```

| layout | что показывает | поля |
|---|---|---|
| `none` | без оверлея (обложка — название вшито в видео) | — |
| `title` | крупный заголовок + подзаголовок | kicker, title, text |
| `text` | заголовок + 1–3 абзаца | kicker, title, text |
| `text-image` | текст + референс | kicker, title, text, images[0], caption |
| `gallery` | сетка 2–6 картинок с подписями (мудборд, раскадровка) | kicker, title, text, images, caption |
| `palette` | цветовые плашки с HEX | kicker, title, text, `colors: [{ hex: "#E8612C", name: "…" }]` |
| `quote` | крупная фраза | kicker, text (фраза), caption (подпись) |
| `video` | аниматик/референс с кнопкой play, без автоплея | kicker, title, text, `video`, `poster`, caption |

Картинки и видео для шаблонов кладите в `assets_src/content/` — скрипт сожмёт их в `assets/content/<имя>.webp` (или `.mp4`, звук сохраняется). Картинка без `src` или с битым путём показывается серым плейсхолдером. Пока играет видео из шаблона, фоновая музыка молчит.

Размещение плашки на кадре (так сделаны все сюжетные остановки master–scene09):

| Поле | Смысл |
|---|---|
| `box` | место плашки — один вариант или список вариантов по порядку предпочтения: `{ x, y, w }` или `{ x, y, r }` — левый верхний угол и ширина (или правый край) в процентах видеокадра; `x < 0` — плашка может начинаться на размытом поле сбоку от кадра в широком окне; `max` — предел ширины в rem (по умолчанию 40); `size` — своя форма для этого варианта; `avoid: "left"` — у кнопок звука и текста справа вверху закончиться левее них (иначе плашка опускается под них) |
| `keep` | что на кадре нельзя закрывать: `{ "Комбик": [x1, y1, x2, y2], … }` в процентах кадра (Комбик, шары, лицо Деда Мороза, продукты, логотипы) |
| `size: "compact"` | компактная плашка «морозное стекло»; кегль текста 17–18 px |
| `size: "strip"` | низкая полоса: заголовок слева, текст справа — когда свободна только узкая полоса над объектами (три шара в невысоком окне) |
| `scrim: false` | без общего затемнения кадра — читаемость держит сама плашка (у вступления — мягкая подложка прямо за текстом) |
| `more: { title, colors }` | раскрываемый блок под текстом, например палитра «Свет и цвет». На экране — только образцы и названия (ориентиры по цвету), HEX остаются в `config.js` |
| `textDelay` | своя пауза перед текстом, с (у разделов тритмента 0,3) |
| `label` | подпись точки навигации, если у слайда нет заголовка (обложка, логотип) |

Как выбирается место (`app.js`: `fit`, `place`). На компьютере берётся первый вариант `box`, где текст целиком помещается и не задевает `keep`, кнопки справа вверху и навигацию; место пересчитывается при изменении окна. В окнах шире 37:20 (например, 1280×600, 2560×1080) сюжетный кадр показывается целиком, по бокам — его размытое продолжение: так над шарами и рядом с лицом Деда Мороза остаётся место для полного текста. На телефоне, в окнах 4:3 и уже и в невысоких окнах (до 580 px) кадр — карточкой, а текст стоит рядом с ней целиком: в вертикальном положении — под карточкой, в горизонтальном — колонкой справа. Если текст физически не помещается, видны заголовок и начало (сначала убираются последние абзацы, потом строки), остальное — по «Читать дальше», с прокруткой внутри плашки.

Проверка: у каждой остановки в `keep` перечислено всё важное на кадре — если меняете кадр или текст, поправьте и `keep`, и варианты `box`.

Для разделов тритмента (после истории, в хронометраж ролика не входят) есть широкая плашка и два шаблона:

- `gallery` с `wide: true`, `cols` (число колонок) и `flow: true` (стрелки между кадрами — последовательность); на телефоне кадры идут списком;
- `timeline`: `timeline: [{ t, label, poster }]` — ширина отрезка пропорциональна длительности, в отрезке кадр сцены, под отрезками шкала с засечками каждые 5 с; `zoom` и `background` у отрезка — кадр шириной в `zoom` отрезков вместо обрезки и цвет полей (логотип целиком в узком высоком отрезке); `notes: [{ term, text }]` — колонки «термин — описание»; `caption` — строка или список примечаний.

На маленьком экране длинная плашка раздела прокручивается внутри себя; колесо и свайп листают сайт, только когда её дальше крутить некуда.

Мудборды (`moodboards` у `gallery`, сейчас в «Как устроен мир»): `[{ title, src, preview, original, w, h }]` — `src` — WebP для просмотра, `preview` — уменьшенная копия для превью, `original` — исходный PNG (кнопка «Оригинал» открывает его в новой вкладке), `w×h` — размер исходника; `moodNote` — подпись в просмотре. На компьютере превью стоят слева и справа от вводного текста, в окне уже 1000 px — рядом под ним. По нажатию мудборд открывается поверх сайта во весь экран: нажатие на кадр (или `+` / `−`) увеличивает его — не меньше исходного размера и вдвое крупнее вписанного, — дальше прокрутка, мышью — перетаскивание, на телефоне — движение пальцем; `← →` и стрелки внизу — другой мудборд, `Esc` и крестик — закрыть. Пока просмотр открыт, клавиши, колесо и свайпы сайт не листают. Веб-версии сделаны из исходников так (FFmpeg из той же сборки, что и для `optimize`):

```
ffmpeg -i moodboard-room.png -c:v libwebp -quality 92 -compression_level 6 -preset picture moodboard-room.webp
ffmpeg -i moodboard-room.png -vf "scale=960:-2:flags=lanczos" -c:v libwebp -quality 86 -compression_level 6 -preset picture moodboard-room-preview.webp
```

Параметры остановки — рядом с `content`: `frame: { fit: "contain", background }` — кадр целиком на любом экране, поля залиты цветом фона ролика (логотип 2:1), или `frame: { fit: "contain", fill: "ambient" }` — поля заполнены размытым продолжением кадра (пэкшот scene09 на 16:10 и 21:9); `backdrop` — фон раздела без своего видео (кадр тритмента, размытый и затемнённый); `section: true` — раздел тритмента (точка-кольцо в навигации, отделена промежутком); `finale: true` — завершение тритмента (без точки в навигации, вне счётчиков).

Счётчик считает историю и разделы отдельно: «01 / 10» … «10 / 10», затем «Решения 1/3» … «Решения 3/3». На последнем кадре истории (логотип) кнопка «Вперёд» становится подписанной кнопкой «Режиссёрские решения»; сам кадр остаётся чистым. Последний экран — «Спасибо!» (`layout: "finale"`: одно слово на размытом кадре комнаты, внизу — `caption`, подпись авторов); на нём счётчик пуст, а «Вперёд» скрыта.

Чтобы на телефоне и в очень широком окне кадр был виден целиком, остановке задаётся `mobileFrame` — рядом с `content`, не внутри (сейчас он у всех сюжетных остановок):

```js
scene09: {
  mobileFrame: { fit: "contain", fill: "ambient" },
  content: { … },
},
```

На телефоне, планшете, в окнах 4:3 и уже, в невысоких (до 580 px) и очень широких (от 37:20) окнах видео показывается целиком, без растяжения и обрезки, а свободное место заполняется: `fill: "ambient"` — размытое продолжение кадра (движется вместе с видео), `"glow"` — тёмная дымка в цвете сцены (`tint: "220 120 50"`); `frame: "card"` — кадр-карточка со скруглёнными углами (только на телефоне и в узких или невысоких окнах; в широком окне кадр во всю высоту). В обычном окне компьютера (от 4:3 до 37:20) кадр, как и раньше, заполняет экран.

Текст появляется через `defaults.textDelay` (1,5 с) после прихода на остановку — сначала чистый кадр — и не появляется заново при повторе цикла. Кнопка в правом верхнем углу и клавиша `T` скрывают и возвращают текст на всех слайдах.

Остановка из тура, для которой нет ни одного файла, показывается тёмным фоном с пометкой «кадр в работе» — так тур можно собрать целиком заранее.

## Склейки и заглушки

`config.js → defaults` задаёт значения для всех рёбер, `edges["from>to"]` — для конкретного:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `join` | `"crossfade"` | как пролёт переходит в цикл: `cut` — прямо (кадры совпадают), `crossfade` — растворение, `push` — растворение с продолжением наезда (последний кадр пролёта увеличивается и размывается, цикл проявляется из лёгкого отъезда) |
| `joinDuration` | `0.5` | длительность склейки, с |
| `push` | `{ outScale: 1.15, outBlur: 6, inScale: 0.94, inBlur: 8 }` | параметры `push` |
| `loopExitFade` | `0.3` | кроссфейд из текущего кадра цикла в первый кадр пролёта (0 — склейка встык) |
| `waitLoopEnd`, `maxWait` | `false`, `2` | дождаться конца итерации цикла перед пролётом, но не дольше `maxWait` с |
| `transitSpeed` | `1.25` | ускорение промежуточных сегментов длинного пути |
| `loopMode` | `"loop"` | `pingpong` — два элемента по очереди, если на стыке цикла заметен рывок |
| `stub`, `stubDuration` | `"fade"`, `1.2` | заглушка для рёбер без видео: `fade`, `push` или `doors` |
| `textLead` | `0.3` | текст уходит за столько секунд до начала пролёта |

Авто-реверс наследует склейку своего ребра зеркально, на старте: если у ребра `a>b` стоит `push`, то в обратном пролёте `b → a` цикл `b` «отъезжает» и размывается, а пролёт проявляется из наезда.

Заглушки (`stubs["from>to"]`, обратное направление — зеркально):
- `doors` — наезд на двери и тёплый свет, из которого проявляется следующий кадр (сейчас на `intro>master`);
- `push` — наезд из одного цикла в другой: первый увеличивается и размывается, второй проявляется из лёгкого отъезда; обратно — отъезд (сейчас на `closeup>globes`);
- `fade` — кроссфейд с лёгким зумом (по умолчанию для всех остальных рёбер без видео).

При `prefers-reduced-motion` все пролёты заменяются кроссфейдами между циклами.

## Музыка

`assets_src/audio/music.*` → `assets/audio/music.mp3`. Если исходника нет, остаётся текущая музыка из манифеста. Стартует при открытии дверей с плавным нарастанием до `music.volume` (0.5). Прокрутка колесом браузером не считается действием пользователя — если двери открыли колесом, музыка включится по первому клику или клавише. При возврате на обложку затихает, при повторном входе продолжает с того же места. Кнопка звука в правом верхнем углу и клавиша `M`. Нет файла — кнопка скрыта, всё работает без звука.

## Навигация

Колесо / тачпад, свайпы, кнопки внизу, точки (переход по кратчайшему пути), клавиши: `→ ↓ PageDown Space` — вперёд, `← ↑ PageUp Shift+Space` — назад, `Home` / `End`, `Enter` на обложке — открыть, `F` — полный экран, `M` — звук, `T` — скрыть/вернуть текст, `D` — отладка. Текущий слайд хранится в адресе (`#globes`): при перезагрузке открывается он же, сразу его цикл.

## Отладка

`index.html?debug=1` или клавиша `D`: текущий узел, играющий сегмент и его время, найденный путь, состояние всех видео-буферов (`readyState`, буфер), рёбра, где сейчас заглушки, PSNR стыков из манифеста. Кнопки: проиграть любой сегмент (включая реверсы и заглушки) и замедлить всё до 0.25× для проверки склеек.

## Деплой на GitHub Pages

1. Создайте репозиторий на GitHub и загрузите в него папку проекта:
   ```
   git init
   git add .
   git commit -m "Тритмент"
   git branch -M main
   git remote add origin https://github.com/<логин>/<репозиторий>.git
   git push -u origin main
   ```
2. На GitHub: **Settings → Pages → Build and deployment → Deploy from a branch**, ветка `main`, папка `/ (root)`.
3. Через минуту сайт будет на `https://<логин>.github.io/<репозиторий>/`.
4. Для красивого превью в мессенджерах замените в `index.html` относительный путь в `og:image` на абсолютный: `https://<логин>.github.io/<репозиторий>/assets/image/og-preview.jpg`.

Файл `.nojekyll` отключает обработку Jekyll. `assets_src/` сайту не нужен и указан в `.gitignore`, поэтому в репозитории не хранится. Старые исходники для работы не нужны: скрипт берёт уже сжатое из `assets/` и `assets/manifest.js` и только дополняет их. Поэтому `assets/` обязательно храните в git — это единственная копия готовых материалов.

После каждого `optimize` закоммитьте изменения в `assets/` и `config.js` и сделайте `git push` — Pages обновится сам.

## Браузеры

Проверено в Chromium (Microsoft Edge): по `file://` и по http, десктоп и мобильная ширина, `prefers-reduced-motion`, блокировка автоплея. Firefox и Safari на этой машине нет — код рассчитан на их актуальные версии, но проверьте вручную.
На iOS громкость музыки программно не меняется (ограничение Safari), поэтому она включается и выключается без плавного нарастания. В режиме энергосбережения iOS блокирует автоплей — сайт показывает постер и «Нажмите, чтобы начать».
