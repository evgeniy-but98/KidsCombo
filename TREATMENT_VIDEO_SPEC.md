# Режиссёрский тритмент «Кидз Комбо × Снежные шары» — видео-версия. ТЗ для разработки

## 0. Как работать

1. **Прежде чем верстать, проверь, какие скиллы для фронтенда у меня установлены** (frontend-design, ui-ux-pro-max и другие, что найдёшь в списке доступных скиллов), прочитай их `SKILL.md` и следуй им во всём UI: типографика, кнопки, индикатор прогресса, экран загрузки, анимации текста.
2. Изучи файлы в `assets_src/` (ffprobe, первые и последние кадры).
3. Предложи архитектуру и план по этапам и **дождись моего подтверждения**. Потом реализуй поэтапно (раздел 13), с коротким отчётом после каждого этапа.

## 1. Суть проекта

Одностраничный статический сайт — режиссёрский тритмент анимационного ролика в формате «презентации». Действие в новогодней комнате. Каждый слайд — **остановка**: камера стоит у объекта, играет зацикленное видео (лёгкое движение), поверх появляются текст и графика. Переход к следующему слайду — **видео пролёта камеры**, анимированное в Kling. Сайт сшивает остановки и пролёты в непрерывный «фильм», который зритель листает.

## 2. Жёсткие требования

- Только статика: HTML + CSS + vanilla JS, без сборщика и фреймворков. GSAP допускается, но положи его локально в `vendor/`.
- Работает и по двойному клику на `index.html` (`file://`), и на GitHub Pages. **Никаких ES-модулей, fetch и JSON-файлов**: конфиг и манифест подключаются обычными `<script>` и пишут в `window.CONFIG` / `window.MANIFEST`.
- **Никакой прокрутки и скроллбаров**: `html, body { overflow: hidden; height: 100%; margin: 0 }`, нативный скролл подавлен (`wheel` с `passive: false` + `preventDefault`).
- Навигация только переходами: колесо мыши/тачпад, кнопки «назад/вперёд», клавиши, свайпы (раздел 9).
- Фоновая музыка стартует после открытия двери (раздел 8).
- Все ассеты сжимаются через FFmpeg (он установлен), раздел 10.
- Видео заполняет экран по принципу cover (`object-fit: cover`) при любых пропорциях окна.

## 3. Исходные файлы

`assets_src/video/`:

| Исходный файл | Тип | id / ребро | Что это |
|---|---|---|---|
| ИНТРО_ЦИКЛ.mp4 | цикл остановки | `intro` | Двери с названием проекта (обложка, текст вшит в видео) |
| ОБЩИЙ_ПЛАН_ЦИКЛ.mp4 | цикл остановки | `master` | Общий план комнаты |
| ШАРЫ_ЦИКЛ.mp4 | цикл остановки | `globes` | Крупный план: три снежных шара с табличками |
| ПОДЛЕТ_КОМБИКУ.mp4 | пролёт | `master → globes` | Пролёт от общего плана к столу с Комбиком |

Все исходники: H.264, 1280×720, 24 fps, без звука, 5–7 с. Музыка (`music.*`) появится в `assets_src/audio/`.

**Уже выявленные особенности:**
- Циклы хорошо стыкуются сами с собой: первый и последний кадр почти совпадают.
- Любой кадр цикла `master` близок к первому кадру пролёта, поэтому пролёт можно начинать в любой момент цикла с коротким кроссфейдом (~0.3 с), не дожидаясь конца цикла.
- **Последний кадр пролёта НЕ совпадает с первым кадром `ШАРЫ_ЦИКЛ`**: пролёт заканчивается средним планом стола, а цикл шаров — это более крупный план. На этом стыке нужна «склейка» (раздел 6, параметр `join`). Позже я, возможно, догенерирую недостающий кусок: добавиться он должен без правки кода.
- **Пролёта «открытие дверей» (`intro → master`) пока нет** — на его месте заглушка (раздел 7).

## 4. Модель: граф остановок и пролётов

- **Остановка (stop)** — узел графа: `id`, цикл (видео, **или** статичная картинка как временный фолбэк), постер (первый кадр в webp для мгновенного показа), контент слайда.
- **Пролёт (transition)** — ребро `from → to`: видео, которое проигрывается один раз.
- **Обратное направление:** если нет отдельного файла `to → from`, скрипт сжатия генерирует **реверс** видео (`-vf reverse`). Отрицательный `playbackRate` в браузерах не работает, поэтому реверс — только заранее отрендеренным файлом.
- **Тур** — упорядоченный список остановок в `config.js` (что показывается кнопками вперёд/назад). Тур не обязан совпадать с рёбрами: переход между соседями тура ищется в графе.
- **Поиск пути:** при переходе от A к B движок ищет кратчайший путь по рёбрам (BFS, с учётом реверсов). Например, если есть только `master → globes` и `master → tree`, путь `globes → tree` = реверс(`master → globes`) + `master → tree`. Промежуточные остановки проезжаются **без паузы** (их циклы не показываются), промежуточные сегменты можно ускорять (`transitSpeed` в конфиге, по умолчанию 1.25).
- **Нет пути** → заглушка-переход (раздел 7), чтобы тур никогда не ломался.

### Добавление новых кадров (главный сценарий на будущее)

Я буду постоянно добавлять новые циклы и пролёты из Kling. Это не должно требовать правки кода:
- кладу файлы в `assets_src/video/` по **соглашению об именах**:
  - `stop__<id>.mp4` — цикл остановки;
  - `tr__<from>__<to>.mp4` — пролёт;
  - `tr__<to>__<from>.mp4` — необязательный «ручной» обратный пролёт, отменяет авто-реверс;
  - `still__<id>.webp|png` — статичная картинка для остановки, у которой ещё нет цикла;
- запускаю скрипт сжатия → он кодирует новые файлы (уже сжатые пропускает по дате изменения) и **генерирует `assets/manifest.js`** со списком всех остановок и рёбер, длительностями и путями к постерам;
- добавляю id в `tour` в `config.js` и пишу контент слайда.

Четыре текущих файла с кириллическими именами переименуй по этой схеме один раз: `stop__intro`, `stop__master`, `stop__globes`, `tr__master__globes`.

## 5. Воспроизведение без швов

- **Двойная буферизация:** минимум два `<video>` элемента (A/B) друг над другом, при необходимости третий для предзагрузки. Следующий сегмент заранее загружен, поставлен на кадр 0 и на паузу (кадр уже отрисован). В момент смены он выходит наверх и стартует — без чёрных кадров и «мигания».
- Момент конца сегмента ловить точно: `requestVideoFrameCallback`, где поддерживается, иначе `timeupdate` + запас на последний кадр. На `ended` полагаться только как на страховку.
- Атрибуты: `muted playsinline preload="auto"`, без `controls`.
- **Цикл остановки:** сначала атрибут `loop`. Если в каком-то браузере на стыке заметен рывок — переключение на пинг-понг двух элементов. Выбор задаётся флагом в конфиге.
- Старт пролёта из цикла: сразу по команде, с кроссфейдом `loopExitFade` (по умолчанию 0.3 с) из текущего кадра цикла в первый кадр пролёта. Альтернативный режим `waitLoopEnd: true` (для будущих циклов, которые плохо стыкуются с пролётом) — дождаться конца итерации цикла, но не дольше `maxWait`.
- Всегда показывать постер, пока видео не готово, — никаких пустых экранов.

## 6. Склейки на стыках (`join`)

Для каждого ребра в `config.js` можно задать, как пролёт переходит в цикл следующей остановки:
- `cut` — прямой переход (кадры совпадают);
- `crossfade` — растворение за `joinDuration` (по умолчанию 0.5 с);
- `push` — растворение + продолжение движения камеры: последний кадр пролёта продолжает мягко увеличиваться (scale 1 → ~1.15) и чуть размывается, цикл остановки проявляется со scale ~0.94 → 1 и blur → 0. Смена плана читается как продолжение наезда.

Для `master → globes` сейчас ставь `push`. По умолчанию для всех рёбер — `crossfade`. Длительность и параметры настраиваются в конфиге.

## 7. Заглушки

- **Открытие дверей (`intro → master`) пока не существует.** Заглушка: по кнопке «Открыть» или по первому листанию камера наезжает на цикл дверей (scale 1 → 1.35), на центр кадра накатывает тёплый свет (радиальный градиент → почти белый-тёплый), затем из света проявляется цикл `master` (scale 1.08 → 1). Длительность ~2 с. В обратную сторону — зеркально.
- **Общая заглушка для любого отсутствующего ребра:** кроссфейд с лёгким зумом (~1.2 с).
- Как только появляется файл `tr__intro__master.mp4` (или любой другой недостающий пролёт) и манифест пересобран, движок автоматически использует видео вместо заглушки.
- **Остановки без видео:** если у остановки только `still__<id>` — картинка с медленным Ken Burns (scale 1.0 → 1.04 за ~20 с). Так тур можно собрать целиком заранее и постепенно заменять картинки видео.

## 8. Музыка

- `<audio loop preload="auto">`, стартует в момент открытия дверей с fade-in громкости до ~0.5 за 2–3 с.
- **Прокрутка колесом не считается пользовательской активацией**, и `audio.play()` от неё отклоняется. Поэтому:
  - на обложке заметная, но стильная кнопка «Открыть» (клик = активация);
  - если двери открыли колесом и `play()` отклонён — ловим rejected promise и запускаем музыку при первом `pointerdown`/`keydown`;
  - при любом клике на обложке «разблокируем» аудио заранее (play → сразу pause).
- Кнопка mute/unmute в углу, клавиша `M`, плавные фейды.
- При возврате на обложку музыка плавно затихает; при повторном входе продолжает.
- Музыки пока нет: если файла нет, всё работает без ошибок, кнопка звука скрыта.

## 9. Навигация

- Колесо/тачпад: копим `deltaY`, срабатывание при пороге ~60, сброс накопления после 200 мс тишины. Во время перехода ввод блокируется, плюс cooldown ~400 мс после — чтобы инерция тачпада не пролистывала несколько слайдов.
- Если во время пролёта пришла команда в ту же сторону — поставить в очередь (максимум 1), в обратную — игнорировать.
- Кнопки «назад/вперёд» внизу: полупрозрачные, в стиле проекта. «Назад» скрыта на обложке, «вперёд» — на последнем слайде.
- Индикатор прогресса (точки или `03 / 15`). Клик по точке — переход по кратчайшему пути в графе с ускоренными промежуточными сегментами.
- Клавиши: ← → ↑ ↓ PageUp PageDown Space, `F` — полноэкранный режим, `Home`/`End`.
- Свайпы на тач-устройствах.
- Текущий слайд в `location.hash`. При перезагрузке открывается он же: сразу его цикл, без пролётов; музыка — после первого клика.

## 10. Сжатие ассетов (FFmpeg)

Скрипт `scripts/optimize` под мою ОС (Windows → PowerShell `.ps1`; определи и предложи). Берёт из `assets_src/`, пишет в `assets/`, генерирует `assets/manifest.js`.

- **Видео:** H.264 High, `-crf 21 -preset slow -pix_fmt yuv420p -movflags +faststart -an`, короткий GOP (`-g 24 -keyint_min 24`) для быстрого старта и точных переходов. Разрешение исходное; если придут 1080p-исходники — оставлять 1080p.
- **Реверсы** для всех пролётов без «ручного» обратного файла.
- **Постеры:** первый и последний кадр каждого видео → WebP (`-quality 85`). Первый кадр цикла — постер остановки; последний кадр пролёта — для склейки `push` и отладки.
- **Статичные картинки:** WebP `-quality 82`, ширина не больше 2560.
- **Музыка:** MP3 ~160 kbps.
- Инкрементальность: не перекодировать то, что не изменилось.
- Итоговая таблица «было / стало».
- Предупреждения: цикл, у которого первый и последний кадр сильно различаются (PSNR ниже порога — рывок на стыке); пролёт, чей последний кадр сильно отличается от первого кадра цикла целевой остановки, — подсказка поставить `join: "push"` или догенерировать кусок.

## 11. Текст и графика на слайдах

- Текст появляется, когда остановка «приехала» (запустился цикл), со stagger по элементам. Уходит за ~0.3 с до начала пролёта.
- **Реальных текстов пока нет — нужен шаблон.** Контент задаётся структурой в `config.js`:
  ```js
  content: {
    layout: "text",           // шаблон, см. ниже; "none" — без оверлея
    side: "left",             // где свободное место в кадре: left | right | center | top | bottom
    theme: "dark",            // dark = светлый текст на тёмном фоне, light = наоборот
    kicker: "Сцена 03",
    title: "Снежные шары",
    text: "Абзац…",
    images: ["assets/content/ref1.webp"],
    caption: "Подпись"
  }
  ```
- Шаблоны: `title` (заголовок + подзаголовок), `text` (заголовок + 1–3 абзаца), `text-image` (текст + референс), `gallery` (сетка 2–6 референсов с подписями — мудборд, раскадровка), `palette` (цветовые плашки с HEX), `quote` (крупная фраза), `video` (встроенный аниматик или референс с кнопкой play, не автоплей).
- Для `intro` по умолчанию `layout: "none"` — название уже вшито в видео дверей; есть только кнопка «Открыть».
- Видео-фоны подвижные и насыщенные, поэтому читаемость обеспечивается мягкой подложкой (градиентная виньетка со стороны текста, лёгкий `backdrop-filter: blur` на плашке — по стилю из скиллов) и тенью текста.
- Заполни все слайды заглушками, показав на них все шаблоны: «Сцена N — {id}», lorem-ipsum на русском, серые плейсхолдеры картинок. Отсутствующие поля не рендерятся.
- Для будущих слайдов, которых ещё нет в видео, заведи в туре 3–4 заглушки-остановки (без файлов — нейтральный тёмный фон с надписью «кадр в работе»), чтобы было видно, как тур растёт.
- Картинки контента: `assets_src/content/` → сжимаются тем же скриптом.

## 12. Загрузка, производительность, отладка

- Экран загрузки в стиле проекта с прогрессом. Обязательно загружаются цикл `intro`, постеры всех остановок и шрифты; остальное подгружается фоном.
- Стратегия предзагрузки: текущий цикл + пролёты к соседям по туру (в обе стороны) + циклы соседей. Далёкие сегменты не держать в памяти.
- Мобильные: muted + playsinline. Если автоплей заблокирован (iOS в режиме энергосбережения) — показать постер и «нажмите, чтобы начать».
- `prefers-reduced-motion`: пролёты заменяются кроссфейдами между циклами.
- **Отладочный оверлей** по `?debug=1` или клавише `D`: текущий узел, играющий сегмент и его время, найденный путь, состояние буферов A/B, `readyState` и `buffered` предзагруженных видео, список отсутствующих рёбер (где работает заглушка). Кнопки: проиграть любой сегмент, замедлить до 0.25× для проверки стыков.

## 13. Этапы

1. Скрипт сжатия + генерация манифеста + структура проекта + `config.js` с туром и заглушками.
2. Плеер: двойная буферизация, циклы, пролёты, поиск пути, реверсы, заглушки, склейки `join`.
3. Навигация (колесо, кнопки, клавиши, свайпы, hash), отсутствие скроллбаров.
4. Обложка с кнопкой «Открыть», заглушка открытия дверей, музыка.
5. Шаблоны контента, типографика и UI по моим фронтенд-скиллам, прогресс, экран загрузки.
6. Отладочный оверлей, проверка в Chrome, Firefox, Safari (если есть), `README.md`: как добавлять видео по соглашению об именах, как пересобрать манифест, как заполнять контент, как поменять склейки, как задеплоить на GitHub Pages.
